# Bili2Text Plus V2｜抖音在线视频下载功能改造报告

**改造日期：**2026 年 11 月 4 日  
**修复开发分支：**`fix/douyin-online-download-403`  
**修复代码提交：**`da30d62`（短 SHA）  
**最终交付目标分支：**`feature/subtitles-and-study-notes`

## 一、改造背景与目标

原项目已具备抖音链接识别能力，但常规 `yt-dlp` 请求抖音视频详情接口时出现 HTTP 403，导致在线下载无法完成。本次目标是在不破坏 B站、YouTube 及原有桌面界面的前提下，实现「抖音链接 → 下载视频 → 提取音频 → Whisper 转写 → Markdown 保存」。

## 二、改造方法与技术实现

1. **采用经过验证的上游修复方案。**参考 `yt-dlp` PR [#17826](https://github.com/yt-dlp/yt-dlp/pull/17826)，固定使用 `viking1304/yt-dlp` 的提交 `728fe46fbaa97d6f03efcaf9e766d4db63338b8d`。该补丁针对抖音详情请求签名及部分下载请求问题进行适配。
2. **隔离下载环境。**修复版要求 Python ≥3.11；实际使用 Python 3.13.12 在 `%LOCALAPPDATA%\Bili2TextPlus\douyin-yt-dlp-728fe46-py313` 创建独立虚拟环境。主项目仍使用 Python 3.10.11，原有 `yt-dlp` 不被覆盖。
3. **新增 `douyin_backend.py`。**负责校验抖音链接、以 `subprocess` 参数数组调用独立环境的修复版 `yt-dlp`、检查下载文件和缓存路径、复用已有视频，并在失败时提供明确报错。
4. **接入现有处理链。**在 `utils.py` 中仅将抖音下载分支转接到新后端；下载的 MP4 继续交给原有音频提取、Whisper 和结果保存流程，`window.py` 无需重新设计。
5. **修复特殊转写问题。**在 `speech2text.py` 中加入「带 `initial_prompt` 转写为空时，去掉提示词重试一次」的处理，并新增 `tests/test_douyin_backend.py` 的 16 项单元测试；同步修改 README 安装说明。

**实现流程：**抖音 URL → 平台识别 → 独立 `yt-dlp` 下载 → MP4 缓存 → 音频提取 → Whisper small → `transcript.md` / `transcript.json`。

## 三、测试与验收

- **真实下载：**公开视频 `6961737553342991651` 下载成功；MP4 为 1080×1920、约 5.99 MiB，约 19.7 秒。验收日志包含下载完成记录。
- **实际转写：**Whisper small 生成 4 段非空文本，输出 407 字节的 `transcript.md`，同时生成 JSON 和任务清单。
- **界面与缓存：**GUI 操作、缓存复用、关闭后重新启动并再次转写均有运行记录；用户另行测试一个短视频也成功。
- **回归测试：**WorkBuddy 报告原有 160 项加新增 16 项，共 **176/176 通过**。本次上传的验收包不含单元测试的完整原始输出。

## 四、已知限制及结论

修复版 `yt-dlp` 仍是上游**未合并**补丁，后续可能因平台接口变化失效；更换电脑需重新安装独立环境。抖音字幕发现仍可能失败并回退 Whisper；识别文字与近似时间码需要人工核对。现有证据支持**短视频的在线下载和转写已实际跑通**，不代表所有视频都能保证成功。

**结论：**本轮完成了抖音在线下载能力的实质性补强，并复用既有桌面 UI 与转写处理链，可作为 Bili2Text Plus V2 的增量改造成果提交。
